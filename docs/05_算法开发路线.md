# 算法开发路线

本路线遵循“先完整工程基线，再增加研究算法；自由运动与接触运动分开；RL 只做最后几毫米残差修正”。

## P0：当前框架

- 固定 UR5e、夹爪、服务器、盘位和腕部 F/T MuJoCo 模型。
- `core` 合同、MuJoCo 适配器、任务阶段和限力门。
- 验收：L2 模型、命名、动力学和 F/T 信号链。

## P1：固定目标的最小闭环

目标：不用视觉，给定 `T_world_disk`，实现单盘 `home → reach → grasp → pull → insert → release → home`。

- 在 `kinematics` 实现阻尼最小二乘 IK。
- 在 `planning` 实现五次多项式或梯形速度轨迹。
- 碰撞查询使用 MuJoCo/Pinocchio/FCL，不能通过削弱碰撞体让规划通过。
- 记录机械臂误差、抓取稳定性、插拔峰值力和任务时间。

## P2：经典接触控制

目标：在没有学习算法时完成稳定低速插入。

```text
raw F/T → tare/gravity compensation → filter → contact detector
        → admittance or force/position control → safety → robot adapter
```

- 先做接触检测和确定性停止/退回。
- 再实现单轴速度—力控制，最后升级为导纳。
- 自由空间轨迹与高频接触控制必须由明确状态切换，不让 MoveIt 接管接触环。

## P3：机架定位

第一版只定位整个服务器机架，不逐个识别硬盘：

```text
T_base_disk_i = T_base_camera · T_camera_rack · T_rack_disk_i
```

- 可先用 AprilTag，再增加 RGB-D 几何估计。
- 盘位模板和标定结果必须携带 frame、时间戳和误差估计。

## P4：轨迹优化

- 使用 Pinocchio 提供正式 FK/Jacobian。
- 自己组织 task、平滑、碰撞、关节限位、奇异性和可操作度代价。
- MoveIt/OMPL 仅作为对照，比较成功率、计算时间、长度、平滑性、最小间隙和可操作度。

## P5：Residual RL 局部修正

只有经典导纳基线达到 L4 后再加入：

```text
nominal pose + admittance correction + clipped RL residual
                                      ↓
                   deterministic safety filter
```

RL 允许输出：`Δy、Δz、Δroll、Δpitch` 等局部小修正；插入轴、最终速度和停止条件由传统控制器掌握。禁止策略直接输出关节力矩。

训练先在 MuJoCo 进行，并随机化初始位姿、摩擦、接触刚度、传感器噪声和时延。真机只做小范围、低速、受保护验证。

## P6：ROS 2 和真机

- `adapters/ros2` 实现与 MuJoCo 相同的 arm/gripper/F/T 端口。
- ROS 2 负责驱动、TF、参数、rosbag、RViz、launch 和 watchdog。
- 先完成 L5 只读映射，再单独批准 L6 运动。

MPC 不是前置条件。只有经典轨迹和接触控制跑通、且确有在线轨迹修正需求时再评估。
