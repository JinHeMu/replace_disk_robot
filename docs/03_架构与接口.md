# 架构与接口

## 依赖与所有权

`task / planning / contact / safety → core ports ← adapters/mujoco`。

算法由项目掌控；MuJoCo 提供仿真、模型与几何查询，ROS 2 适配层仍未实现。核心类型和算法层不得导入 MuJoCo、ROS 或厂商 SDK。MoveIt 不是主链依赖。

通用运动学、轨迹规划、优化及碰撞查询保留；新增测力动作是位于 MuJoCo 后端的验收夹具，不是插入算法。`contact` 已提供通用 wrench 坐标变换/滤波和导纳柔顺，但尚无闭环插入控制器。

## 保留接口

- `Pose`：显式坐标系、米制位置、wxyz 四元数。
- `Wrench`：同一显式坐标系下的 N、N·m。
- `JointState`：命名关节、rad，拒绝缺失/重复/非有限状态。
- `load_model()`：从仓库内绝对路径装配模型；`reset_home()`：恢复已夹持初始状态及配套平衡控制量。
- `MujocoRobotAdapter`：按关节名交换位置目标，保留夹爪米制开口与原始控制量接口。当前理想夹持锁定指关节，不支持松盘。
- `MujocoWristFTAdapter`：`raw()`、`tare()`、`wrench()`、`read_wrench()`，输出 frame 为 `wrist_ft_site`。
- `WrenchProcessor`：把传感器 wrench 旋转到指定输出 frame、把力矩参考点平移到 TCP、转换为外部载荷并做低通/死区；不依赖 MuJoCo。
- `KeyboardAdmittanceController`：把按键 `CartesianJog` 积分为有界名义位姿，叠加 `AdmittanceController` 柔顺偏移并输出修正位姿；提供名义超前限幅，防止碰到障碍后参考继续累积。
- `CartesianServo.submit_pose()`：位姿跟踪入口，把 base frame 的位姿误差转为限幅 twist 后复用原有阻尼微分 IK；原 `submit()` 速度入口保持不变。
- `MujocoCollisionChecker`：夹持盘计入机器人集合；普通规划查询仍把盘与插口接触判为碰撞，不暗中放行。
- `ForceLimitGuard`：保留独立限力门；不是接触控制器，仍直接读取未滤波的原始力路径。

服务器专用 `MujocoMechanismAdapter` 及其导出已删除。通用核心端口/枚举保留以避免不相关算法接口变更，但不代表场景包含旧机构或会执行旧换盘阶段。

## 场景名称

| 名称 | 含义 |
|---|---|
| `home` | 已夹持初始化 keyframe |
| `replacement_drive_held` / `drive_collision` | 刚性夹持的单一硬盘与碰撞盒体 |
| `drive_center` / `drive_front` | 盘中心/前端参考系 |
| `insertion_socket` / `socket_entry` | 固定通道/入口参考系 |
| `socket_left/right/top/bottom` | 四壁碰撞几何 |
| `wrist_ft_site` / `wrist_force` / `wrist_torque` | 六维测力接口 |
| `overview_cam` / `insertion_cam` / `grasp_cam` | 整体/入口/夹持相机 |

6 个手臂执行器加 1 个夹爪执行器，`nu=7`；两个传感器共 6 维。`task_target` 为通用 FK/IK 示例保留的隐藏参考体，不是附加任务物件。

## 接触验证数据流

加载并重置 → 静止 1 秒 → 去皮 → 局部 IK 生成受限位置目标 → 位置伺服前馈 → 记录六维力与真实接触 → 静止 0.5 秒 → 比较最后 0.1 秒均值。

轴向工况先横向偏移 1 mm，再向入口推进至前端目标超出入口平面 0.05 mm（短边夹持后重新限定的位置验证行程）；侧向工况先对正进入 5 mm，再横移至 0.45 mm 位置目标。受接触约束，实际位置不会等于穿墙目标。验证只运行有限时长，以 10 N / 1 N·m 为中止界限。报告保存原始/去皮 wrench、坐标系、插深、横向偏差、接触对象、峰值穿透、接触反力核对与半时间步比较。
