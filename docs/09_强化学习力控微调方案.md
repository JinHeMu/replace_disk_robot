# 强化学习力控微调方案

日期：2026-09-11

状态：设计方案，尚未实现训练环境、策略或实机控制

## 1. 结论与设计边界

本项目适合采用 **Residual RL（残差强化学习）**，而不是让强化学习直接控制关节位置、关节速度或力矩。

主控制链保持确定性：插入阶段控制器负责沿通道前进和基础导纳修正；RL 仅根据位姿与腕部六维力的短时变化，输出有界的小幅笛卡尔速度修正。RL 输出必须经过残差限幅、Cartesian Servo、关节/工作空间约束和最终安全监督，策略没有直接写 MuJoCo `ctrl` 或未来真实机器人驱动器的权限。

```text
位姿 / 腕部 F/T
       │
       ▼
滤波、去偏、坐标变换、特征构造
       │
       ├──────────────► Residual RL（20 Hz）
       │                         │ 小幅残差速度
       ▼                         ▼
经典插入力控 / 导纳 ───────► 残差融合与限幅
                                  │
                                  ▼
                     CartesianServo（100 Hz）
                                  │
                                  ▼
                  SafetySupervisor / ForceLimitGuard
                                  │ 唯一命令出口
                                  ▼
                         MuJoCo / 未来 ROS 2
```

这一定义中的“力控微调”是：策略利用力信息改变微小的插入、横移和姿态修正速度，使插入过程更顺畅、更少产生侧向卡滞和峰值载荷。它不是纯力矩控制，也不替代确定性安全逻辑。

| `kinematics/ur5e.py`、`kinematics/tool.py` | UR5e FK/Jacobian/IK 与夹持盘 TCP 定义 | 位姿、速度与关节命令之间的转换 |
| `safety/force_limit.py` | 超过力/力矩阈值时将请求目标替换为当前关节位置 | 保留为最终快速限力门，并由更完整的插入安全监督器调用 |
| `adapters/mujoco/insertion_validation.py` | 位置驱动的接触与摩擦场景验收 | 提供 7.5 N 低速阻力基线和仿真一致性回归；不能当训练环境或闭环控制器 |
| `examples/keyboard_servo.py` | 键盘 → Servo → 限力门 → MuJoCo 的单一命令链 | 可复用其调度、看门狗和命令所有权模式，不与 RL 同时运行 |

当前新增但尚未提交的 `AdmittanceController` 已经解决了六轴顺应状态、限幅和坐标系拒绝机制，但尚未接入插入主链。RL 开发前还缺少：wrench 坐标变换与滤波、经典闭环插入基线、插入成功/失败判据、可随机化环境、策略安全包装和统一评估器。

特别需要注意：当前摩擦标定的低速平均阻力约为 7.5 N，但入口/换向峰值可超过 10 N。`7.5 N` 是场景中的持续滑动阻力，不等于控制器必须跟踪的恒定目标力。RL 开发的第一个门槛是先证明经典基线能在选定的生产安全阈值内完成插入；如果 10 N 阈值与当前场景的不可避免峰值冲突，应重新核对真实硬件安全界限、入口过程和场景参数，不能为训练方便静默提高阈值。

## 3. 控制方案

### 3.1 坐标系与频率

建立任务坐标系 `socket_entry`：X 为插入方向，Y 为通道宽度，Z 为厚度方向。所有策略观测和动作都在该坐标系表达。`MujocoWristFTAdapter` 当前输出 `wrist_ft_site`，因此必须先完成 wrench 的旋转与力矩平移，再进入特征构造和基线控制器；不得依赖初始姿态下两个坐标系“看起来一致”。

- MuJoCo 物理步长：保持当前 `0.0005 s`，即 2000 Hz。
- Cartesian Servo 与快速安全检查：100 Hz。
- 经典插入控制器：100 Hz。
- RL 推理：20 Hz，每个动作保持 5 个 Servo 周期。
- RL 动作超过 100 ms 未更新：残差归零，经典基线继续受安全层约束；不保持失联前的非零残差。

训练时可以批量加速仿真，但上述控制周期、滤波截止频率和时延模型应保持一致。

### 3.2 经典基线控制器

在启用 RL 前，先实现可单独工作的 `InsertionController`：

1. 沿 X 轴以低速推进，依据轴向载荷进入“前进、减速、保持、故障”状态。
2. Y/Z 平移和绕 Y/Z 转动使用有界导纳或力位混合修正，目标是降低侧向力和弯矩。
3. 达到 50 mm 插深并满足稳定窗口后判定成功；场景无后挡板，不能用“碰到底”判定成功。
4. 任一传感器无效、数据过期、Servo 超时、跟踪异常或安全阈值越界时，锁存故障并输出保持。
5. `residual = 0` 时必须可以完成名义工况，或以明确、可重复的原因安全失败。

现有 `AdmittanceController` 可用于 Y/Z、绕 Y/绕 Z 的顺应位姿生成。轴向推进与目标载荷区间由 `InsertionController` 明确定义，不应把“实测 7.5 N 阻力”直接作为导纳输入，也不应把 `Wrench` 的符号约定藏在算法内部。

### 3.3 RL 观测

第一版 actor 只使用未来实机也能获得的量，不把 MuJoCo 接触对象、真实接触力或随机化参数泄漏给策略。建议的观测由以下命名特征组成：

| 特征组 | 内容 | 数量 |
|---|---|---:|
| 进度 | 插深 | 1 |
| 对准误差 | Y/Z 偏差、绕 Y/Z 角误差 | 4 |
| TCP 运动 | X/Y/Z 速度、绕 Y/Z 角速度 | 5 |
| 力觉 | 任务坐标系下滤波后的完整 `Fx,Fy,Fz,Tx,Ty,Tz` | 6 |
| 力觉变化 | 上述六维量的一阶差分或稳定滤波导数 | 6 |
| 基线输出 | 基线控制器当前的 5 维笛卡尔命令 | 5 |
| 动作历史 | 上一个实际执行的 5 维 RL 残差 | 5 |
| 合计 | 固定顺序、固定单位、带 schema 版本 | 32 |

每个特征使用配置文件中的物理尺度归一化到约 `[-1, 1]`。超范围值应裁剪并计数，不能在线更新均值方差导致部署分布漂移。训练完成时将特征顺序、归一化参数和 `observation_schema_version` 与模型一起导出。

若后续采用 asymmetric actor-critic，可让 critic 在训练时额外读取接触几何和随机化真值，但 actor 的 32 维输入保持不变。

### 3.4 RL 动作

策略输出归一化 5 维残差：

```text
a = [Δvx, Δvy, Δvz, Δwy, Δwz]
```

第一阶段建议物理上限：

| 动作 | 初始上限 | 说明 |
|---|---:|---|
| `Δvx` | ±0.5 mm/s | 仅微调轴向推进速度，基线仍拥有主进度 |
| `Δvy`, `Δvz` | 各 ±0.3 mm/s | 缓解侧向接触，不允许一次动作跨越间隙 |
| `Δwy`, `Δwz` | 各 ±0.1 °/s | 微调俯仰/偏航，不控制绕插入轴自旋 |

动作还需经过以下确定性限制：动作变化率限制、累计横向/角度偏移限制、任务工作空间限制、Servo 自身速度与关节限制。任务空间命令与最终关节目标分别为：

```text
u_servo = task_limit(u_baseline + residual_limit(u_rl))
q_requested = CartesianServo(u_servo)
q_commanded = InsertionGuard(q_measured, q_requested, wrench, watchdogs)
```

这些只是仿真起始上限，不是实机批准值。后续只能根据仿真验收和硬件风险评估收紧或逐级开放。

### 3.5 奖励与终止

奖励应首先鼓励任务进度，其次减少不必要接触，不应单独奖励“力越小越好”，否则策略可能学会停止不动。

```text
r = 进度奖励
  - 侧向力和弯矩惩罚
  - 轴向载荷超出软区间的惩罚
  - 动作幅值与动作跳变惩罚
  - 时间惩罚
  + 完成奖励
  - 安全故障惩罚
```

轴向力使用软区间而非精确跟踪 7.5 N；软区间上界必须低于硬安全阈值。所有奖励项先按物理尺度无量纲化，权重保存在配置文件中。评估报告除总回报外必须单列成功率、插入时间、峰值/均方力矩、残差裁剪率和安全触发原因，不能用单一 reward 代表控制品质。

终止条件：

- 成功：插深达到 50 mm，横向/角度误差在界内，力/力矩连续稳定若干控制周期。
- 失败：硬力/力矩阈值、非允许碰撞、跟踪错误、传感器非有限或过期、反向退出过界、工作空间越界。
- 截断：达到最大 episode 时间但未成功。

### 3.6 算法选择

首选 SAC：动作连续、样本可复用，适合五维有界残差控制。TD3 可作为对照；PPO 可用于验证结论是否依赖 off-policy 算法，但不建议第一版同时维护多套训练主链。

训练框架只是 `rl/train.py` 的适配依赖。运行时通过一个只接收 NumPy 数组的 `ResidualPolicy` 接口加载策略，`contact`、`control`、`safety` 和 MuJoCo 适配层不得导入训练框架或 PyTorch。

## 6. 随机化与课程学习

策略若只在当前完全对正、固定 7.5 N 阻力场景训练，很可能学到“保持直线前进”，没有研究价值。建议按课程逐级增加难度：

1. **C0 基线**：零残差，固定场景，先验证经典控制器和安全链。
2. **C1 力学变化**：在有测量依据的范围内随机化导轨摩擦、刚度、阻尼、硬盘质量；加入 F/T 零偏和白噪声。
3. **C2 对准误差**：加入亚毫米 Y/Z 偏差和小角度 pitch/yaw 偏差，范围不得让初态直接穿透硬壁。
4. **C3 时序变化**：加入传感器低通、一个策略周期以内的观测/动作延迟和控制周期微小抖动。
5. **C4 留出评估**：使用训练范围外但仍物理可信的组合，只做测试，不继续更新策略。

随机化上下限必须在 `randomization.yaml` 中附来源：实测、标定、制造公差或仅用于鲁棒性压力测试。不要用大范围随机化掩盖场景建模错误。

## 7. 安全与命令所有权

- 每个阶段只允许一个命令所有者。键盘、经典插入、RL 插入不能同时向 Servo 提交命令。
- RL 只能增加小残差；策略异常、模型缺失、输出 NaN、推理超时或 schema 不匹配时立即回到零残差。
- `ForceLimitGuard` 当前只能保持当前关节目标，接触力可能仍然存在。自动退回应作为单独的确定性状态，经仿真和低速硬件验证后才能启用；在此之前采用锁存保持和人工复位。
- 硬阈值不进入 reward 优化，也不能被策略或训练配置覆盖；它只存在于安全配置中。
- 记录 `u_baseline`、原始 `u_rl`、限幅后残差、最终命令和每个裁剪/故障原因，保证问题可追溯。
- 训练进程、曲线或视频处理不得阻塞 100 Hz Servo；沿用当前独立进程、有限队列和丢弃非关键可视化样本的做法。
- 首期只做 MuJoCo。真实机器人顺序必须是离线回放 → 只读观测/shadow mode → 人员在场的低速有界动作，且另行完成急停、数据新鲜度、工作空间和退回策略验收。

## 8. 训练产物与可复现性

`artifacts/rl/<run_id>/manifest.json` 至少记录：

- Git commit 与工作区是否干净；
- 场景、四个 RL 配置文件的校验值；
- observation/action schema 版本与顺序；
- 随机种子、训练算法和依赖版本；
- 特征归一化常量；
- checkpoint、最佳模型和评估报告路径；
- 训练范围、留出范围和已知限制。

大体积 checkpoint、视频、TensorBoard 事件和 replay buffer 默认加入 `.gitignore`。仓库只提交配置、schema、必要的小型测试夹具和最终模型的 manifest；是否提交导出模型应单独决定。

## 9. 实施顺序与验收门

### P0：冻结现有接口

- 先完成当前 `hard_disk_robot → replace_disk_robot` 包名迁移和导纳代码的独立提交。
- 复跑现有单元测试、摩擦标定和半时间步验证，保存干净基线。
- 决定 RL 实验采用的硬安全阈值，并检查它与入口峰值是否物理可行。

### P1：无 RL 的闭环插入

- 实现 wrench 处理、任务坐标变换、`InsertionController` 和 `InsertionGuard`。
- 零残差完成名义 50 mm 插入；失败时原因稳定可复现。
- 在不同时间步和小范围初始偏差下验证控制器，不训练策略。

### P2：环境合同

- 实现随机化 reset、Gym 风格 step、32 维观测、5 维动作、奖励分项和终止原因。
- 用零策略和脚本策略通过环境检查；同一 seed 产生同一初态和轨迹。
- 验证 actor 观测中没有仅仿真可得的信息。

### P3：Residual SAC

- 先训练 C1，再逐步开放 C2/C3。
- 每次训练都同时评估：基线、RL、去掉力观测、去掉随机化四组消融。
- 根据留出集选择模型，不按训练 reward 选择。

### P4：仿真验收

建议初始门槛，可在实现前由项目负责人确认：

- 固定的至少 1000 个未见 seed 上成功率不低于 95%，并显著优于相同安全约束下的基线；
- 最终安全层之后零硬阈值越界，所有安全裁决均有明确原因；
- RL 残差裁剪率足够低，不能长期依赖限幅器完成任务；
- 峰值轴向力、侧向力/力矩和插入时间分别报告，且不以牺牲安全换取成功率；
- 当前时间步、半时间步、名义工况、随机工况和留出工况全部出独立报告；
- 模型加载失败、NaN、超时、观测缺失时均回退为零残差并保持安全。

### P5/P6：实机分级

- P5：真实传感器只读采集和 shadow mode；策略输出只记录，不发送。
- P6：另行批准后进行低速、有界、小批次实机验证；安全层与人工急停独立于 RL。

仿真 P4 通过只说明策略在当前模型及随机化范围内有效，不等于真实硬件安全或完成 sim-to-real。

## 10. 第一轮最小实现范围

建议第一轮只实现下列内容，保持一条清晰主链：

1. `contact/wrench.py` 和 `contact/insertion.py`，先跑通无 RL 闭环插入。
2. `safety/residual_limit.py` 与 `safety/insertion_guard.py`，建立唯一最终命令出口。
3. `rl/features.py`、`rl/residual.py`、`rl/policy.py`，先使用 `ZeroPolicy` 和脚本策略。
4. `adapters/mujoco/insertion_env.py` 与固定 seed 的环境测试。
5. 最后加入 SAC 训练入口、随机化和批量评估。

首轮不做视觉、抓取打滑、关节力矩控制、端到端策略、ROS 2 实机输出或在线学习。这样可以先确认“RL 是否确实改善经典力控难以处理的微小卡滞”，再决定是否扩大动作空间和任务范围。
