# 开发与维护标准

## 1. 当前问题清单

| 优先级 | 问题 | 修改方法 | 完成门槛 |
|---|---|---|---|
| P0 | 服务器与托架仍是通用简化体 | 锁定真实型号并实测 | 参数、照片/CAD、坐标系评审完成 |
| P0 | 无完整接触安全策略 | 增加限速、限位、退回和失败恢复 | L4 多次接触回归无超限 |
| P1 | 无 FK/Jacobian/IK 主链 | 在 `kinematics` 实现并与数值差分验证 | 单元测试和 MuJoCo FK 对照通过 |
| P1 | 无轨迹生成和碰撞规划 | 在 `planning` 实现，几何查询使用成熟库 | 无碰撞预接触和抽插轨迹通过 |
| P1 | 无接触控制 | 在 `contact` 实现滤波、检测和导纳 | 接触力、稳定性和退出条件通过 |
| P1 | 无感知与标定 | 实现机架定位和盘位模板 | 误差统计满足插入公差 |
| P2 | 卡扣与弹出未物理联动 | 根据真实托架建模约束和弹簧 | 时序与实物一致 |
| P2 | 无 ROS 2/真机适配器 | 只在 `adapters/ros2` 实现端口 | L5 只读后才能进入 L6 |
| P3 | 无 MoveIt 对照 | 在 `baselines/moveit` 添加可选实验 | 不得成为核心依赖 |

## 2. 依赖纪律

- `core` 只能依赖 Python 标准库和 NumPy 类型。
- 算法层只能依赖 `core` 和明确批准的数学/几何库。
- 只有 `adapters/mujoco` 可以 import `mujoco`。
- 只有 `adapters/ros2` 可以 import `rclpy`、消息包和厂商驱动。
- MoveIt 代码只能位于 `baselines/moveit`，主测试在未安装 MoveIt 时仍须通过。
- 接触控制和 RL 输出必须经过 `safety`，安全规则不得放进神经网络。

## 3. 增加算法的标准流程

1. 先写任务卡：问题、数学、输入输出、单位、坐标系、失败方式和验收等级。
2. 在 `core.ports` 检查是否已有接口；接口变化先更新合同测试。
3. 在对应算法目录实现，不直接读写 MuJoCo `qpos`/`ctrl`。
4. 写 Toy/NumPy 验证，再与 MuJoCo 或 Pinocchio 交叉验证。
5. 先运行 L0/L1，再运行 headless L2；涉及接触才进入 L4。
6. 报告分为“已验证、未验证、仿真假设、真实硬件风险”。

## 4. 算法所有权

- 自己实现：IK 迭代框架、插值/轨迹生成、轨迹代价、导纳/力位控制、任务状态机、Residual RL 接口与安全限制。
- 使用成熟库：URDF 解析、Pinocchio 刚体运动学、FCL/ESDF 距离查询、数值优化器、ROS 2 通信、神经网络框架。
- MoveIt：只做 baseline、可视化验证和显式 fallback。

判断标准：如果替换一个库，维护者必须能说明其输入、输出、数学意义、失败条件以及为何得到当前结果。

## 5. 每次提交前检查

```bash
python3 scripts/smoke_test.py
python3 -m unittest discover -s tests -v
git diff --check
```

涉及场景或碰撞几何时，还必须生成/检查固定相机图像，确认没有初始穿模、错误接触、坐标轴错误或抽拉方向错误。

## 6. 真机前硬门槛

- `command_output_enabled` 默认必须为 `false`。
- 明确急停、速度/力/力矩/位移限制以及服务器热插拔政策。
- 完成机器人—服务器外参、TCP、指尖和 F/T 零点/重力标定。
- 先做软质治具，再做报废托架，最后才接真实服务器。
- L5 只读成功不等于 L6 可运动，L6 必须单独评审授权。
