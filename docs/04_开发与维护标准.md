# 开发与维护标准

## 依赖纪律

核心合同和算法层不导入 MuJoCo、ROS 或厂商 SDK。后端专用模型读写、接触查询与测试夹具位于 `adapters/mujoco`；人工运行入口与测试可导入后端。算法需放入相应算法模块，不能逐渐堆进验收示例。

保留关节名称、wxyz 四元数、显式力坐标系和 m/rad/N/N·m 单位。新增算法先明确输入输出、坐标系、命令所有权和失败条件，再做小规模验证。

## 场景修改检查

```bash
conda activate hard_disk_robot
python examples/check_isolated_environment.py
python examples/smoke_test.py
python -m pytest -q
python examples/validate_insertion_contact.py --output simulation/mujoco/reports/contact_validation.json
MUJOCO_GL=egl python examples/capture_scene.py
git diff --check
```

场景或碰撞几何变动必须检查三张固定相机图像，并核对 0.25 mm 单侧间隙、5 秒保持、50 mm 插深几何路径及接触穿透。不能通过扩大开口、屏蔽盘与插口碰撞或跳过失败测试宣称完成。

Conda 激活负责隔离宿主 ROS/NumPy/Pinocchio ABI；环境更新后重新激活并执行检查。模型与网格保持仓库内自包含。

## 证据与后续硬件

报告分清几何采样、动力学保持、接触测力、闭环插入和实机结果。当前 `command_output_enabled=false` 仅记录硬件输出默认意图，不是实际硬件联锁。

后续实机必须先完成坐标系/TCP/力传感器与工具重力标定，再做只读验证；硬件运动另行评审。限力门不能替代闭环稳定性、速度约束、故障退出和物理急停。
