# 功能规格与验收标准

## 1. 工程目标

为固定式 UR5e 更换服务器前置 2.5 英寸热插拔硬盘建立一个分层仿真框架。当前交付重点是模型、命名、坐标系、任务合同、测试入口和维护规则，不是换盘算法本身。

## 2. 目标任务序列

1. 安全预检：确认机器人、夹爪、服务器和目标盘状态。
2. 目标定位：取得锁扣、把手、盘位与暂存区位姿。
3. 预接触：无碰撞到达锁扣法向前方。
4. 按压锁扣：使用受限速度和 F/T 保护接触按钮。
5. 弹出：释放锁扣并让托架进入可夹持位置。
6. 夹取旧盘：夹持托架把手并确认抓取稳定。
7. 抽出旧盘：沿服务器插拔轴抽出，监视轴向力和偏载力矩。
8. 放置旧盘：放入旧盘暂存区并松爪。
9. 夹取新盘：从新盘暂存区取得替换盘。
10. 对准：对齐盘位中心、姿态和插入轴。
11. 插入：低速受力插入并完成最终就位。
12. 验证：检查托架位移、锁扣状态和服务器侧状态。

阶段名称和完成事件的机器可读草案见 `config/task_sequence.yaml`。

## 3. 功能边界

| 模块 | 当前状态 | 本阶段完成定义 |
|---|---|---|
| UR5e 刚体与执行器 | 已有并复用 | 6 个关节按名称可控，home 稳定 |
| 2F-85 | 已有并复用 | 单一 0–255 指令可张合 |
| 腕部六维 F/T | 本次新增 | 3 维力 + 3 维力矩可读、可去皮 |
| 2U 服务器 | 本次新增简化体 | 尺寸、盘位和碰撞体可用 |
| 目标托架/锁扣 | 本次新增简化体 | 抽拉、按压自由度和执行器可用 |
| 替换硬盘与暂存台 | 本次新增 | 自由刚体可被未来抓取算法使用 |
| 任务状态机 | 仅合同 | 不执行动作，只定义阶段/完成事件 |
| 力控 | 仅信号链和阈值门 | 不声称恒力或顺应控制已实现 |
| 真实机器人 | 未接入 | 不在当前验收范围 |

## 4. 本阶段验收

执行：

```bash
python3 scripts/smoke_test.py
python3 -m unittest discover -s tests -v
```

必须满足：

- 装配场景 `simulation/mujoco/scene.xml`（含 vendoring 进来的 UR5e/2F-85 模型）可通过 `load_model()` 从任意工作目录加载，不依赖仓库外的文件。
- 模型不存在 NaN/Inf，连续仿真至少 1000 步。
- 6 关节 home 保持最大误差小于 `0.025 rad`。
- 夹爪驱动关节运动量大于 `0.05 rad`。
- 目标托架与锁扣到达给定位置允许误差。
- 施加 `12 N` 外载后，去皮腕部力增量在 `10–14 N`。
- `8 N` 阈值门在上述外载下阻断新的关节目标。

## 5. 验证等级

- L0：接口、名称、单位、坐标系和任务合同静态检查。
- L1：模型合同与 Python 单元测试。
- L2：无界面 MuJoCo 动力学/信号链测试。
- L3：可视化、无接触的整段换盘轨迹。
- L4：包含锁扣、抓取、抽出和插入的接触闭环测试。
- L5：真实设备只读、标定和状态映射。
- L6：经过风险评审的真实机器人低速动作。

当前交付达到 L2；阈值门不等于 L4 力控。只有完成对应等级全部验收后，才能在文档中声称达到该等级。
