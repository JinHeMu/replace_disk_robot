# 1013_06 接触后俯仰方向与传感器坐标核查

只读分析 `samples.jsonl`、`metadata.json` 和日志保存的 URDF/XML。06 包 12404 行，99.224 s，记录完整且无丢行。没有连接机械臂或更改在线参数。

## 结论

这里的约 20° 指 **传感器原始六轴量到 `tool0` 的软件旋转矩阵** 与 URDF/XML 所定义传感器轴的差异；并不是硬盘、夹具或者机械臂在安装时实际转了 20°，更不是导纳要求机械臂转 20°。06 包的在线矩阵来自 `tool/ft_gravity_samples_identified.json` 中的 `sensor_to_tool_rotation`；加载 JSON 时它会覆盖代码默认值。两套矩阵相差约绕工具 X 轴 +20.009°。URDF 和 XML 对传感器轴的定义彼此一致，力臂长度都为 195 mm。

06 包在无手柄角速度输入的接触窗口，处理后的正向工具 X 力矩进入俯仰导纳；修正参考及实测姿态沿该方向转动。对于当时工具姿态，工具 Y 几乎向上，工具 Z 向前，工具 X 几乎向左，绕工具 X 正向旋转会使硬盘插入端**低头**。这与用户感觉上下俯仰方向不对相符；没有看到 Servo 或关节反馈把俯仰方向再次取反的证据。

## 差异所在

从记录中的模型计算，传感器轴到 `tool0` 的旋转近似为：

```text
R_model = [[-0.7072, +0.7070,  0],
           [-0.7070, -0.7072,  0],
           [ 0,       0,      +1]]
```

实际在线加载的是：

```text
R_online = [[-0.7071, +0.7071,  0],
            [-0.6644, -0.6644, -0.3422],
            [-0.2419, -0.2419, +0.9396]]
```

`R_online × R_modelᵀ` 的轴角约为工具 X 方向 `+20.009°`。20° 体现在 Y/Z 混合：若真实力轴与模型轴一致，沿工具 Z 向后 5 N，当前转换会显示约 `Fy=+1.71 N、Fz=-4.70 N`。按当前 `r_sensor_from_TCP=[0,0,-0.195] m` 换算到插入端，`Tx = Tx_direct + 0.195 Fy`，单是这项混合就产生约 `+0.334 N·m` 的俯仰力矩，超过当前 0.2 N·m 死区。若只有向后轴向阻力，本应没有这样的俯仰力矩。

代码路径：原始读数 → JSON 指定的传感器姿态用于重力补偿 → 残余六轴量旋转到 `tool0` → 195 mm 力臂换算到插入端 → 滤波、死区 → 导纳旋转 → Servo。当前 JSON 的旋转来自历史外参常量；旧代码注释称它来自 WBMM，但当前 WBMM `jaka_hardware_interface.cpp` 只输出原始六轴读数，未找到该矩阵。不能据此判定实际传感器轴一定等于 URDF 的 `jk_se_vi_200_link`。

## 06 包接触窗口

下表 `Tx` 是当前矩阵得出的插入端未滤波俯仰力矩；`模型轴假设 Tx` 是将**同一批已记录的补偿残余**按 URDF 传感器轴重新表达并换算的离线灵敏度分析。俯仰变化由关节反馈经日志 URDF 重新计算；正值约表示插入端低头。各窗口的手柄角速度指令为 0。

| 时间 s | 当前 Fz 均值 N | 当前 Tx 均值 N·m | 模型轴假设 Tx 均值 N·m | 实际工具 X 转角 |
|---|---:|---:|---:|---:|
| 29–32 | -23.91 | +1.61 | -0.02 | +0.905° |
| 32.5–34.5 | -19.50 | +1.26 | -0.04 | +0.535° |
| 48.5–52 | -9.66 | +0.44 | -0.21 | +0.634° |
| 57.2–59.1 | -9.99 | +0.37 | -0.30 | +0.491° |

29–32 s 的当前 `+1.61 N·m` 包含传感器直接力矩约 `+1.01 N·m` 和力臂项约 `+0.60 N·m`。因此“伪横向力经力臂产生俯仰”只是机制之一，直接力矩经过旋转及当时真实接触也有贡献。旋转导纳速度上限为 0.005 rad/s，约 0.286°/s；29–32 s 期间接近持续触发。已记录的修正姿态到最终下发姿态差很小，方向是在 Servo 之前形成。

## 解释边界与修正顺序

离线重表达**不等于**换矩阵后的真实控制结果：变更 `sensor_to_tool_rotation` 也会改变用于重力补偿的传感器姿态，已有质量、重心、偏置和额外去皮必须配套重新辨识或验证。当前 06 包无法独立证明 JAKA SDK 原始六轴数据与 URDF 传感器 link 的实际轴严格一致；紧配合槽口的双边摩擦、接触点也可能影响真实力矩方向。

修正应先在不接触槽口的状态下核实六轴方向：悬空检查各姿态零载残余；在插入端沿已知的工具 ±Z、±Y 方向施小的已知力，再施已知抬头/低头力偶，记录 SDK 原始量、补偿残余、`external_tcp_unfiltered` 和滤波后力矩。比较 `R_online` 与 `R_model` 哪个能够保持：纯轴向力基本不虚构俯仰、正负力偶的俯仰符号正确、换姿态后零载残余小。确认实际轴后统一 URDF/XML 与在线旋转外参，重新拟合该轴定义下的重力/偏置，再用只读 dry-run 验证，最后低速低力验证导纳方向。仅将俯仰导纳取反会把与 Fz 相关的错误隐藏起来，其他接触方向仍可能错。

19.5 cm 目前只是用户提供的传感器**表面**到插入端距离；传感器内部测量原点和可能的横向偏心尚未独立测量。力臂误差也会改变力矩，但不能解释两套旋转矩阵的 20° 差异。
