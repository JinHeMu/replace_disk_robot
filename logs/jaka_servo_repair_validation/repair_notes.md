# Servo 延迟放大修复与全链路审阅

2026-10-12。全部验证均为离线或 MuJoCo，未连接、使能或运动实机。

## 修复了什么

旧位姿跟踪用 `参考位姿 - 实测位姿` 生成速度，却把这一速度积分到**持续保存的下发关节目标**。当执行器反馈滞后时，尚未执行完的运动会被重复累加。这与日志中约 1 Hz 的振幅放大相符；纯延迟模型也能独立复现这一机制。

新版 `control/servo.py` 使用以下方式生成运动：

1. 连续参考的位移、空间旋转增量提供前馈，减少原先位姿比例跟踪带来的附加滞后。
2. 纠偏使用 `上一周期参考 - 上一周期下发关节目标的 FK`，使纠偏状态与 IK 积分状态一致。使用上一周期参考，是为了避免本周期参考增量在前馈和纠偏中重复计算。
3. 纠偏系数为 `(1-exp(-gain*dt))/dt`，使理想单轴纠偏在合法控制周期内保持单调收敛。
4. 首次命令没有前馈；停止、复位、切换到速度模式、命令超时及提交中断后清除历史。

实测关节仍用于跟踪误差保护和实际位置到候选目标之间的碰撞检查。现有笛卡尔速度、关节速度、关节限位、命令/循环超时、力保护均保留。直接速度命令路径保持原算法。用户已有 YAML 参数没有被本次修改覆盖。

本修复消除了 Servo 对延迟误差的重复积分，并减少软件位姿跟踪附加的滞后；**并未消除机器人内部约 140 ms 的有效跟随延迟，也未完成自适应插入状态机。**

## 力处理 → 导纳 → Servo 审阅

| 环节 | 本次结论与处理 |
|---|---|
| EDG 采样 | 同一数据包提供关节状态和原始六维力；两份旧日志没有明显循环超时或丢行。传感器内部时间戳和控制器滤波状态仍未提供。 |
| 重力、偏置及 TCP 换算 | 启动残余低于死区，日志中 `tau=R*tau_sensor+r×F` 代数自洽。未发现可以据此直接改符号的证据。0.4 m 力臂是否对应实际控制点仍需实物确认。 |
| 低通和死区 | alpha=0.2、125 Hz，低频滤波群延迟约 32 ms；1 N/0.5 Nm 为硬死区。保留参数和算法，以便下一份日志隔离 Servo 修复的影响。不能把滤波的这部分滞后计作已经修复。 |
| 六轴导纳 | 独立逐周期重算公式与日志一致；单独的 M-D-K 为过阻尼。接触中频繁触发平移/旋转速度饱和，且力臂会将横向力耦合到旋转，整体接触闭环仍可能振荡。 |

| Servo | 已修复延迟误差重复积分，加入轨迹增量前馈和命令空间纠偏。 |
| 力保护和 SDK 下发 | 力保护输入和阈值保留；日志新增保护实际使用的六维力。SDK 返回成功仅表示适配器接受命令，不能表示机器人已经执行。 |

## 离线与仿真证据

延迟模型为纯位置执行延迟，不包含真实接触刚度、摩擦或机器人内部滤波。它用于隔离 Servo 算法，不能替代实机验收。

在 144 ms 延迟、1 Hz、2 mm 幅值的模型中：

| 指标 | 修复前 | 修复后 |
|---|---:|---:|
| 实际振幅 / 参考振幅 | 1.672 | 1.000 |
| 下发振幅 / 参考振幅 | 1.672 | 1.000 |
| 下发相对参考相位 | +2.97° | 约 0° |
| 实际相对参考相位 | -48.87° | -51.84° |

实际相位仍包含执行延迟，不能将振幅修复理解成实际相位也已经消除。单轴旋转的同条件结果相同。0/72/144/200 ms 延迟、0.5/1/2 Hz、平移与旋转合计 24 组均未见新版振幅放大。

使用真实 JAKA 运动学、相同历史 corrected_pose 和固定 18 样本延迟重放：

| 旧日志有效段 | 参考→下发位置 RMS，前/后 | 参考→延迟实际位置 RMS，前/后 |
|---|---:|---:|
| trial_001，首次保护前 | 0.425 / 0.010 mm | 0.842 / 0.710 mm |
| trial_002，有效激活段 | 0.571 / 0.046 mm | 1.084 / 0.829 mm |

该回放保持原参考不变，没有假设修改后的接触力也会与旧日志相同；不能用它预测实机插入一定成功。

相关 Servo、延迟、力处理、导纳、手柄和日志/分析测试 **126 项通过**。新增覆盖包含受阻固定目标不超调、延迟阶跃、速度限制、停止/超时历史清除和实测跟踪保护。

MuJoCo 检查走生产手柄节点、力传感器补偿、导纳、Servo、力保护和关节位置执行器，**53 项全部通过**，结果见 [joy_mujoco_report.json](joy_mujoco_report.json)。其精细模式位移门槛现按 RB 缩放，原有精细/正常速度比例检查保留；手柄旋转测试显式指定 4°/s，避免依赖用户 YAML 中的 0.5°/s 设置。这两项仅为验证代码调整。

完整仓库测试另有原有问题：两个轨迹测试引用不存在的 `planning.optimize`；旧键盘重构对照测试有 23 项失败，在未修改 Servo 的临时基线中同样复现。相关测试未通过不应被表述为“全仓测试全绿”。

新增记录包括力处理起止、参考完成、Servo 完成时间戳，Servo 候选目标和力保护后最终命令各自的 TCP 位姿、前馈/纠偏/限速后速度及力保护输入。它们用于分离软件计算耗时、参考到命令误差和命令到实测响应；保护触发时也能区分计算过的候选目标与真正发送的保持命令。

```bash
python3 src/replace_disk_robot/applications/jaka_joy/jaka_joy_node.py --backend real --log-dir logs/jaka_joy_trial_003
```

使用新目录，避免覆盖旧数据。先记录一小段无接触的小幅运动及停止，再记录居中接近、轻触/短时推进；出现抖动即松 LB，结束本次记录后再进行其他手动操作。尽量标注各段大致顺序和首先接触的槽边。实机改善幅度以这份新日志为准。
